Task 4.1 - Locate the Defects:
------------------------------
Defect 1: Catastrophic Partition Asymmetry on Sorted Data
In the provided quicksort, the pivot is fixed as the last element: p = a[hi].
When the array is already sorted:
- The last element is always the maximum element in the current range.
- The partition loop compares every element a[j] with p. Since all elements <= p,
  index i advances all the way to hi - 1.
- The partition produces subproblems of size (n - 1) and 0!
- The recursion recurrence becomes T(n) = T(n - 1) + O(n) = O(n^2).
- Total comparisons explode to n(n - 1)/2 = 49,995,000 for n = 10,000.

Defect 2: Call Stack Overflow Vulnerability
Because the subproblems are partitioned into (n - 1) and 0, the recursion tree does not
split logarithmically; it forms a degenerate linear chain of depth n = 10,000.
Each stack frame consumes memory for local variables and return addresses (~48 bytes/frame).
At n = 100,000 or under default restricted thread stacks, this instantly exhausts the stack,
crashing the server with a segmentation fault / stack overflow.

Defect 3: Inherent Algorithmic Instability
Lomuto partitioning swaps distant elements across the partition boundary (e.g. swap(&a[i], &a[j])).
When two students have equal marks, an earlier student can be swapped across a later student,
scrambling their relative roll number order and resulting in published rank discrepancies each year.

Task 4.3 - Repaired Quicksort Implementation:
---------------------------------------------
Three systematic engineering repairs were implemented in `quick_fixed.c`:
1. Median-of-Three Pivot:
   Picks the median of {a[lo], a[mid], a[hi]} as pivot. On sorted, reverse-sorted, or nearly-sorted
   inputs, this guaranteed the pivot is near the exact 50th percentile, preventing O(n^2) degradation.
2. Tail-Recursion Elimination:
   Recurse on the strictly smaller half first and iterate the larger half with a while-loop.
   This mathematically proves that the maximum stack depth CANNOT exceed floor(log2(n)) <= 14 frames!
3. Small Range Cutoff (Cutoff = 16):
   Subarrays of length <= 16 are sorted using Insertion Sort, eliminating recursive call overhead.

Task 4.4 - Rules for Choosing a Sorting Algorithm for Real Data:
----------------------------------------------------------------
Rule 1: Never assume input is random. Always guard against pre-sorted, reverse-sorted, and repeated
        data by using randomized/median-of-three pivots or hybrid introspection (IntroSort/Dual-Pivot).
Rule 2: If secondary key order matters (e.g. preserving submission timestamp or student roll number
        for equal marks), strictly require a STABLE sort (Merge Sort, Timsort, or Counting Sort).

Alternative Concept & Complexity Analysis:
------------------------------------------
1. Merge Sort:
   - Time Complexity: O(n log n) in ALL cases (best, worst, average). Guaranteed predictable latency.
   - Extra Space: O(n) auxiliary buffer for temporary merging.
   - Stability: Strictly STABLE when using '<=' in merge.
2. Counting Sort (Marks 0 to 100, k = 101):
   - Time Complexity: O(n + k) linear time! For n = 100,000 and k = 101, runs in < 1 ms.
   - Extra Space: O(k) for frequency counters + O(n) output buffer.
   - Stability: Strictly STABLE when accumulating backward. Highly recommended for exam marks.
